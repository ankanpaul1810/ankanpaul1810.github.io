Why CNN over rule-based?

Scalability and generalization under varying lighting conditions. Rule-based systems fail with shadows, reflections, and color variance.

Why SqueezeNet?

Edge deployment constraints + sub-second latency requirements. Needed <5MB model size for IoT devices with limited compute.

What failed?

Initial false positives under smoke-only conditions. Solved by expanding training data with ambiguous fire/smoke scenarios.

Failure Modes & Trade-offs

• Higher accuracy models (ResNet50+) increased latency beyond edge limits (3s+ vs <1s requirement)
• Prioritized model size over marginal accuracy gains — 94% at 5MB beat 96% at 40MB for deployment
• Sacrificed multi-scale detection for inference speed — focused on standard viewing distances

Why SSE over WebSockets for progress?

Simpler architecture with uni-directional flow. Background processing only needs server→client updates, not bi-directional. Reduced complexity and connection overhead.

Plan-aware limits architecture?

MongoDB schema with usage tracking and middleware-enforced quotas. Free/Pro/Max tiers with graceful degradation. Scalable without external quota services.

Why session-based auth over JWT?

Meeting data sensitivity required immediate revocation capability. Session store provides instant logout and better security control than stateless tokens.

Failure Modes & Trade-offs

• Whisper chunk size tuned to balance cost vs coherence — smaller chunks reduced API cost but fragmented context
• SSE chosen over WebSockets for simpler reliability guarantees — sacrificed bi-directional features for stability
• Plan-aware limits enforced pre-processing, not mid-stream — prevented partial failures but required upfront quota checks

Why Google Sheets over database?

Zero deployment overhead + non-technical user familiarity. Existing workflow integration was critical for adoption.

WhatsApp + Email strategy?

Multi-channel redundancy. Different user groups preferred different channels — built for 100% delivery rate.

Error handling?

Retry logic with exponential backoff + manual fallback queue. Zero tolerance for failed payroll distribution.

Failure Modes & Trade-offs

• WhatsApp rate limits forced batch delays — prioritized guaranteed delivery over instant distribution
• Google Sheets API quota constraints required careful throttling — sacrificed speed for reliability
• Chose dual-channel redundancy over single optimized path — increased complexity but eliminated single point of failure
